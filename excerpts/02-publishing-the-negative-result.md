# Excerpt — publishing the negative result

**Component:** evidence-linked knowledge layer between raw experience and executable procedures
**Status:** closed / parked; hypothesis partially unproven

## What was built

An evidence-linked knowledge wiki sitting between raw execution experience and executable
procedures, so that cross-case interpretation, provenance, contradictions and failed routes
have somewhere to live that is not the procedure file itself.

## Verified state at closure

- 6 frozen evidence corpora; 58 evidence units
- 81 artifact references checked: **80 still match their frozen hashes**; 1 had declared,
  documented drift after the freeze
- 16 domain pattern pages, 9 method pages, 3 continuity-related pages
- 4 protected baseline procedures preserved: 2 unchanged, 2 with explicitly declared later drift
- Verifier result: `PASS_WITH_DECLARED_DRIFT`; a second safety-mode verifier: `PASS`
- One first-of-its-kind outcome: a batch that concluded **"no durable learning"** because the
  existing validator already enforced the observed lesson — the correct answer was to add
  nothing

## What it did demonstrate

The layer works as **persistent knowledge middleware**:

- it accumulates cross-case interpretation;
- it preserves provenance, contradictions and failed routes;
- it avoids pushing all history and rationale into the procedure file;
- it supports later-agent retrieval — a fresh session, with no access to the originating
  conversation, recovered the correct verified route from the wiki alone;
- it can return **zero** pages when a lesson is already enforced elsewhere;
- it can produce isolated, reversible evolution candidates rather than direct edits.

## What it did NOT demonstrate

> It has **not** shown that wiki-mediated procedure evolution is better than direct
> experience-to-procedure editing. No blind controlled comparison of equivalent candidates has
> run, and the live pilot produced no logged natural tripwire evidence.

The closure document says exactly this, and the next gate is written down: run one isolated
direct-versus-wiki evolution experiment, blind-evaluated against an unchanged baseline, before
adding another domain or changing another live procedure.

## Why the negative framing is the point

A component left running without an honest verdict is a liability — it accumulates
maintenance, looks like progress, and quietly influences decisions. Recording "the passive
layer is validated, the central architecture claim is not" is what made it safe to stop and
park.

This is the standard applied to every component in this repository: **a claim without a
gate is not a result.**
